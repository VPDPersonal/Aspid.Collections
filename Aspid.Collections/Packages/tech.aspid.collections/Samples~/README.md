# Интерактивные примеры Aspid.Collections

Пять самостоятельных сцен показывают, как использовать наблюдаемые коллекции в игровых интерфейсах. В каждой есть готовые данные, кнопки действий, видимый результат, счётчики и короткое задание. Журнал скрыт в **+ Events** и хранит последние три события.

| Пример | Задача | Что изучить |
| --- | --- | --- |
| [Squad Roster](SquadRoster/README.md) | Состав отряда | Одиночные и пакетные события списка, `Move`, `Replace`, `CreateSync`, освобождение карточек |
| [Item Browser](ItemBrowser/README.md) | Каталог с поиском | Цепочка `FilteredList`, категории, сортировка, явный `Update()` после изменения свойства |
| [Crafting Queue](CraftingQueue/README.md) | Очередь крафта и отмена | FIFO-очередь, LIFO-история, пакетное добавление, проекции очереди и стека |
| [Match Scoreboard](MatchScoreboard/README.md) | Результаты матча | Словарь по ID, замена значения, сохранение остальных представлений, comparer ключей |
| [Zone Occupancy](ZoneOccupancy/README.md) | Учёт посетителей зоны | Уникальность в `HashSet`, отсутствие событий для дубликатов, отдельная подписка `SplitByEvents` |

## Запуск

1. В **Package Manager → Aspid.Collections → Samples** импортируйте нужный пример.
2. Откройте `Scenes/<имя примера>.unity` внутри импортированной папки.
3. Запустите **Play Mode** и воспользуйтесь кнопками над данными. В `SquadRoster` и `MatchScoreboard` номера `View` показывают, сохранились ли объекты представления.

Сценам нужен встроенный модуль **UI Toolkit** (`com.unity.modules.uielements`, версия `1.0.0`). В обычных Unity-проектах он уже включён. Если модули были удалены из минимального проекта, установите его через Package Manager перед импортом примеров. Дополнительные библиотеки, TextMeshPro, Input System и внешний шрифт не требуются: IBM Plex и лицензия находятся в каждом примере. Сам runtime Collections по-прежнему работает без движка и без этого модуля.

Рекомендуемый размер Game View — **1600 × 1000**. Интерфейс масштабируется через `PanelSettings`, длинное содержимое прокручивается. Кнопки работают мышью, поиск — вводом текста; `Tab` переключает фокус. Сцены используют UI Toolkit. Кнопка **Light / Dark** переключает светлую и тёмную темы. При запуске в Editor тема следует его оформлению; в сборке по умолчанию тёмная. Одна короткая подсказка описывает действие, а журнал и технические счётчики доступны в **+ Events**. Подробные объяснения остаются в руководствах.

## Как читать код

Начните с `Scripts/<имя примера>Sample.cs`: `OnEnable` создаёт источник и его представления, затем связывает действия с кнопками. Предметные данные выделены в `CrewMember`, `CatalogItem`, `WorkOrder` и `PlayerScore`. В `Scripts/Presentation/` находится оформление карточек и небольшой `SamplePanel` для привязки кнопок и журнала; его можно пропустить при изучении API Collections.

Каждый пример содержит собственные сборку, UI, шрифты, настройки панели и сцену. Примеры можно импортировать по отдельности или вместе. Небольшой вспомогательный код повторяется намеренно: общего примера, который пришлось бы импортировать первым, нет.

## Правила жизненного цикла

- Создатель `CreateSync`, `CreateFiltered` и `SplitByEvents` владеет возвращённым объектом и вызывает его `Dispose()`.
- `OnDisable` сначала отвязывает кнопки и свои обработчики, затем освобождает представления, затем источники. Повторное включение создаёт чистый сеанс без дополнительных подписок.
- В `CreateSync(..., isDisposable: true)` элементы представления реализуют `IDisposable`. Для обычных `VisualElement` используется перегрузка с явным обработчиком удаления.
- Модели не знают об UI. У источников есть только данные и события; представления предоставляются через интерфейсы для чтения.
- Изменения коллекции наблюдаются автоматически. Изменения полей её элементов сами по себе не создают событие коллекции.
- Все действия выполняются на главном потоке. `FilteredList` нельзя параллельно изменять и перечислять с другого потока.

Пределы числа элементов нужны только для удобства демонстрации. Здесь нет сетевого транспорта, сохранения прогресса и серверной проверки результатов: соответствующие кнопки локально имитируют такие изменения данных.
