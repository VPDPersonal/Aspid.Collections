# Производительность и проверка

## Используйте поддерживаемые пакеты операций

AddRange/InsertRange/RemoveRange списка и пакетные операции Queue/Stack отправляют пакет вместо повторяющихся одиночных событий. Sync списка, очереди и стека передаёт поддерживаемые пакеты. Пустые пакеты игнорируются. Dictionary и HashSet не предоставляют публичных методов пакетного изменения.

Пакеты уменьшают работу рассылки, но не гарантируют отсутствие аллокаций. `SplitByEvents` превращает одиночные данные в массив из одного элемента, а основной API событий принимает интерфейс аргументов. Копирование сохранённых пакетных данных тоже имеет стоимость.

## Измеряйте свою цепочку

FilteredList может инкрементально обработать прямое изменение источника, но явный Update, очистка и последующие фильтры цепочки могут перестроить карту индексов. Comparer, преобразование, создание UI и освобождение — работа приложения. Измеряйте её на реальных размерах и способах доступа к данным.

Не выводите показатели .NET из интерактивной иллюстрации сайта. Она работает на JavaScript и объясняет поведение, а не измеряет время .NET.

## Запуск тестов репозитория

```bash
dotnet test DotnetTests/Aspid.Collections.Tests.csproj --configuration Release
```

Для Unity откройте проект разработки `Aspid.Collections/` и запустите PlayMode-наборы в Test Runner. Версия проекта — 6000.6.5f1; минимум пакета остаётся 2021.3.0f1.

Производительные тесты находятся в `Tests/Runtime/Observable/Performance/`. Им нужны Unity Test Framework и `com.unity.test-framework.performance`; без последнего ссылка asmdef не разрешится при компиляции тестов. `ASPID_COLLECTIONS_PERFORMANCE_TESTING` — version define для кода, а не отключение сборки без пакета. Потребителям только ядра не нужно импортировать тесты.

## Актуальность справочника API

Раздел API генерируется из public/protected C#-поверхности runtime через DocFX. После изменения API выполните `npm --prefix Website run api`, затем соберите оба языка. Проект генерации не зависит от Unity.
