# Жизненный цикл и безопасность событий

## Создатель владеет обёрткой

`CreateSync`, `CreateFiltered` и `SplitByEvents` создают подписку. Источник может удерживать этот объект после потери вашей ссылки. Сохраняйте возвращённый handle и освобождайте его при завершении жизни потребителя.

В Unity связывайте `OnEnable` с `OnDisable`, если компонент можно переключать. Сначала снимите UI-callback и свои обработчики, затем освободите последующих потребителей, затем источники. Ниже — порядок завершения для полей такого компонента:

```csharp
// Stop UI callbacks and your own listeners first.
_cards.CollectionChanged -= OnCardsChanged;
_alarm.Dispose();
_visible.Dispose();
_search.Dispose();
_cards.Dispose();
_source.Dispose();
```

В примерах показаны полные создание и завершение. Новый `OnEnable` начинает чистый сеанс без накопления обработчиков.

## Владение источником и элементами

Dispose основной коллекции вызывает Clear, отправляющий Reset, и удаляет подписчиков. Он не вызывает Dispose моделей внутри коллекции. Синхронизированная обёртка может явно владеть освобождением элементов назначения через `isDisposable: true` или callback удаления. Источником она не владеет.

Dispose FilteredList только снимает подписки и слушателей; он не очищает данные. Освобождённый фильтр может сохранять устаревшие индексы. Интерфейсы источников только для чтения не включают IDisposable; предоставляйте их потребителям, сохраняя конкретного владельца в компоненте или сервисе.

## Вложенные изменения и исключения

Рассылка допускает изменение подписок: новые обработчики не входят в текущий снимок, удалённые пропускаются. Это не делает вложенные изменения транзакционными. Избегайте изменения источника из собственного уведомления, когда его слушают несколько проекций.

Исключения обработчиков, преобразования и освобождения передаются вызывающему коду. Источник уже мог измениться, а следующие обработчики — не выполниться; отката нет. Выполняйте потенциально неуспешную проверку до изменения и оставляйте обработчики короткими.

## Потоки и отложенная работа

Callback выполняется на вызывающем потоке. Передавайте изменение на главный поток до изменения UI-источника. Для отложенной обработки копируйте данные, не сохраняя пакетный буфер или активный перечислитель. FilteredList требует доступа с одного потока на всём протяжении жизни.

Независимые подписки показаны в [Zone Occupancy](/tutorials/zone-occupancy), владение объектами назначения — в [Squad Roster](/tutorials/squad-roster).
